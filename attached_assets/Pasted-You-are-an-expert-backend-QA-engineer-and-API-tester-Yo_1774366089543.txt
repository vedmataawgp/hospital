You are an expert backend QA engineer and API tester.

Your task is to test all available APIs in this project and generate a detailed report.

For EACH API endpoint, perform the following checks:

1. STATUS CODE VALIDATION
- Check if the API returns the correct HTTP status code.
- Expected:
  - 200 / 201 → success
  - 400 → bad request (invalid input)
  - 401 → unauthorized (missing/invalid auth)
  - 403 → forbidden (no permission)
  - 404 → not found
  - 500 → server error
- Report if the API is returning incorrect status codes.

2. RESPONSE VALIDATION
- Check if the response body matches the expected format (JSON, object structure, fields).
- Validate:
  - Required fields present or missing
  - Correct data types
  - Null or undefined issues
- Report any mismatch.

3. FILE RESPONSE CHECK (if applicable)
- If API returns a file:
  - Check correct file type (PDF, image, CSV, etc.)
  - Check headers (Content-Type, Content-Disposition)
  - Check file integrity (not corrupted, downloadable)
- Report if incorrect file type or broken file.

4. AUTHENTICATION & AUTHORIZATION
- Test APIs with:
  - No token
  - Invalid token
  - Expired token
  - Valid token
- Verify correct responses:
  - 401 for unauthorized
  - 403 for restricted access
- Check if any API is accessible without required authentication (security issue).

5. ERROR HANDLING
- Send invalid inputs (wrong data types, missing fields)
- Check if API returns proper error messages
- Ensure no internal server crashes (500 errors)

6. EDGE CASE TESTING
- Test:
  - Empty inputs
  - Large payloads
  - Boundary values
- Verify stability and correct responses

7. PERFORMANCE BASIC CHECK
- Measure response time
- Flag APIs taking too long (>2-3 seconds)

8. FINAL REPORT FORMAT

- Endpoint:
- Method:
- Status Code: (Expected vs Actual)
- Response Valid: Yes/No
- Authentication: Pass/Fail
- File Handling: Pass/Fail (if applicable)

- Suggestions:
